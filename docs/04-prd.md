## 1. Overview (обзор)

Beauty Hub MVP — веб-платформа структурированных объявлений типов Space, Event, Vacancy для beauty-индустрии Ростова-на-Дону плюс Telegram как канал и уведомления по **типу** объявления. Matching по Search Intent — не входит.

**Статус продукта:** идея + документация. Рынок не валидирован. `HYPOTHESIS`.

## 6. User journeys (пользовательские пути)

Детальные экраны: [07](07-ux-architecture.md). Здесь — продуктовые сценарии.

### J-1. Мастер: найти кабинет

1. Попадает на сайт или из Telegram.
2. Смотрит каталог без входа. Контакт — только после Telegram Login (DEC-03). См. BH-FR-11, BH-FR-12.
3. Фильтрует Spaces: район, специализация, цена.
4. Открывает карточку, нажимает контакт.
5. Пишет в Telegram/звонит вне платформы.

Успех: состоялся контакт. Подтверждённый съём — вне системы в MVP.

### J-2. Владелец: опубликовать кабинет

1. Вход, роль «владелец помещения / салона».
2. Создание Space: обязательные поля, фото, модерация `pending` → `published`.
3. Карточка на сайте и в канале (после публикации).
4. Отклики приходят в указанный контакт.

### J-3. Организатор: мастер-класс

Аналогично J-2 с полями даты, специализации, лимита мест. Регистрация участников **не** внутренняя платёжка: контакт или внешняя ссылка. `ASSUMPTION`.

### J-4. Мастер: подписка Telegram

1. Связывает бота.
2. Выбирает типы: кабинеты / события / вакансии.
3. При новой `published` карточке этого типа получает сообщение со ссылкой на сайт.

Нет персонального matching по району в P0 (это P1 Search Intent).

### J-5. Жалоба и модерация

Пользователь жалуется → модератор в админке скрывает или отклоняет → статус `rejected` / снят с канала по возможности.

## 7. Functional requirements (функциональные требования)

Легенда приоритета: P0 / P1 / P2. Статус уверенности: C (нужно для гипотезы MVP) / H (гипотеза ценности) / A (assumption реализации).

### BH-FR-01 — Регистрация и вход

| Поле | Значение |
| --- | --- |
| Источник | Исходник: регистрация мастера; Telegram-first |
| Пользователь | Все роли P0 |
| Проблема | Нужна идентичность для публикации и контакта |
| Приоритет | P0 |
| Проверка | Пользователь входит через Telegram Login и получает сессию |
| Метрика | `user_registered` |
| Зависимость | Telegram Bot / Login Widget |
| Уверенность | C; метод auth заморожен: только Telegram Login (DEC-04) |

Рекомендация: Telegram Login как единственный способ в MVP. Email/телефон — P2.

### BH-FR-02 — Роли при онбординге

Роли: `master`, `space_owner` (салон или помещение; включает бывший `salon_owner`), `organizer`. Один пользователь — одна основная роль, смена в настройках допустима. `space_owner` публикует Space и Vacancy. Любая роль с completed-профилем может создать любой из трёх типов (DEC-08).

| Поле | Значение |
| --- | --- |
| Источник | Исходник: «Я мастер / владелец / организатор» |
| Приоритет | P0 |
| Проверка | Роль сохраняется, влияет на CTA создания |
| Метрика | `profile_completed` |
| Уверенность | C |

Роль `brand` не создаётся (DEC-06).

### BH-FR-03 — Профиль

Поля MVP: фото (опционально), имя, специализация (для master; для supply — необязательно), район (справочник Ростова), короткий текст, контакт Telegram, телефон опционально, Instagram опционально.

| Поле | Значение |
| --- | --- |
| Источник | Исходник, этап 2 плана |
| Приоритет | P0 (минимум для публикации: имя + роль + контакт) |
| Проверка | Нельзя опубликовать listing без имени и контакта |
| Метрика | `profile_completed` (все обязательные поля) |
| Уверенность | C |

Верификация «галочка», отзывы, опыт в годах — не P0.

### BH-FR-04 — Справочник специализаций

Значения MVP: `barber`, `hair`, `nail`, `brow`, `lashes`, `makeup`, `cosmetology`. Расширение — админка, не свободный ввод в MVP (`ASSUMPTION`: свободный ввод = мусор).

| Приоритет | P0 |
| Метрика | Использование фильтра specialization |
| Уверенность | A по списку; `RESEARCH REQUIRED` полнота |

### BH-FR-05 — География

Город константа `rostov-on-don`. Район — справочник. Поля Country/Region в БД есть, в UI нет.

| Приоритет | P0 для района на listing |
| Уверенность | C для района; состав seed заморожен в [24 §4.2](24-implementation-spec.md) |

### BH-FR-06 — Listing: Space

Поля: заголовок, описание, район, специализации (для кого), цена (число + период: месяц / смена / час), площадь опционально, фото 1–N, контакт (наследует профиль, можно переопределить), срок жизни (дата истечения или 30 дней по умолчанию `ASSUMPTION`).

| Источник | Исходник: свободные кабинеты |
| Пользователь | Salon / Space Owner |
| Приоритет | P0 |
| Проверка | Карточка в поиске Spaces после `published` |
| Метрика | `listing_created`, `listing_viewed` |
| Уверенность | C |

### BH-FR-07 — Listing: Event

Поля: заголовок, описание, дата/время начала, район или адрес текстом, специализации, цена участия или «бесплатно», лимит мест информативно (без билетного инвентаря), ссылка на внешнюю регистрацию опционально, фото, контакт.

| Приоритет | P0 |
| Метрика | `listing_created`, `event_registered` **не строить**, если нет внутренней записи. Вместо этого `contact_clicked` / `external_link_clicked`. |
| Уверенность | C |

Внутренняя регистрация участников — P2 (риск стать event-платформой).

### BH-FR-08 — Listing: Vacancy

Поля: заголовок, описание, район, специализация, формат (аренда / найм / процент) текстом или enum простой, контакт.

| Приоритет | P0 |
| Источник | Исходник: ищу мастера / ищу работу — **в P0 публикует салон** «ищу мастера». Объявление мастера «ищу работу» = тот же тип от роли master. |
| Уверенность | H для «ищу работу» от мастера: не раздувать. P0: оба направления одним типом `vacancy` с полем `direction`: `looking_for_master` \| `looking_for_job`. |

### BH-FR-09 — Статусы объявления

`draft` → `pending` → `published` \| `rejected` → `expired` \| `archived`.

Публикация в Telegram-канал только из `published`. Истечение — cron/фоновая задача; в MVP допустим daily job в монолите.

| Приоритет | P0 |
| Уверенность | C (без статусов витрина гниёт) |

### BH-FR-10 — Поиск и фильтры

Фильтры: тип, район, специализация, ценовой диапазон (для space/event), дата события (для event), только `published` и не `expired`.

Сортировка MVP: новые сверху. Полнотекст — простой ILIKE / FTS PostgreSQL, не отдельный движок.

| Приоритет | P0 |
| Метрика | `search_performed`, `filter_applied` |
| Уверенность | C |

### BH-FR-11 — Публичный каталог

Просмотр списков и карточек без входа. Контакт скрыт; кнопка «Показать контакт» требует входа (DEC-03). Нужно, чтобы снизить скрейпинг и считать `contact_clicked`.

| Приоритет | P0 |
| Уверенность | C (DEC-03) |

### BH-FR-12 — Контакт

Кнопка открывает `t.me/...` или `tel:`. Платформа не хранит переписку.

| Приоритет | P0 |
| Метрика | `contact_clicked` (прокси, не North Star) |
| Уверенность | C |

### BH-FR-13 — Telegram: привязка и подписка на типы

Пользователь связывает `TelegramAccount`. Подписки: флаги space / event / vacancy. Сообщение при новой публикации этого типа (не персональный район).

| Приоритет | P0 |
| Метрика | `telegram_connected`, `notification_sent`, `notification_opened` (если измеримо: клик по ссылке UTM) |
| Зависимость | BH-FR-09, канал |
| Уверенность | C для гипотезы Telegram-first |

Отписка: команда бота / настройки. Обязательно.

### BH-FR-14 — Telegram-канал

Модератор или система публикует краткую карточку с ссылкой на сайт после `published`. Не дублировать rejected.

| Приоритет | P0 |
| Уверенность | H (канал как витрина привлечения) |

### BH-FR-15 — Жалобы (Reports)

Причины: мошенничество, спам, неверная информация, запрещённый контент, неактуально.

| Приоритет | P0 |
| Метрика | число reports, время реакции (операции) |
| Уверенность | C для trust |

### BH-FR-16 — Админка и модерация

Список pending, approve/reject с комментарием, список reports, просмотр пользователей, снятие published.

| Приоритет | P0 |
| Источник | Исходник: админка обязательна |
| Уверенность | C |

Роль `admin` не публичная.

### BH-FR-17 — Избранное

Сохранить карточку. P1: не блокирует ценность P0 (есть подписка на тип).

| Приоритет | P1 |
| Метрика | saves |
| Уверенность | H |

### BH-FR-18 — Saved Search / Search Intent

Сохранить фильтры; уведомлять только по совпадению. Это **Matching v1**.

| Приоритет | P1 (после беты) |
| Метрика | `match_created`, `notification_sent` |
| Уверенность | H |

Не реализовывать в MVP.

### BH-FR-19 — Каталог мастеров

Поиск людей. P1. Риск Non-Goal «соцсеть».

| Приоритет | P1 / возможно Won't, если интервью не подтвердят |
| Уверенность | H, слабая |

### BH-FR-20 — Collaboration / Model listing

Отдельные типы. P2 до валидации JTBD-07/08/09.

### BH-FR-21 — Аналитика событий

Серверные события по [14](14-analytics.md). P0.

### BH-FR-22 — Юридические страницы

Политика ПДн, правила, удаление аккаунта. P0 для публичной беты. D-02.

### BH-FR-23 — Удаление аккаунта

Пользователь может запросить удаление; объявления снимаются. P0 (152-ФЗ / гигиена).

## 15. Acceptance criteria (критерии приёмки)

Критерии историй: [06](06-user-stories.md). Критерии релиза: [13](13-qa-test-strategy.md) Release checklist + [16](16-launch-plan.md) exit criteria беты.

Продуктовая приёмка MVP (качественная):

- Можно создать и промодерировать три типа карточек.
- Гость видит список, залогиненный пользователь открывает контакт.
- Бот шлёт сообщение подписчику типа при публикации.
- Жалоба доходит до админки.
- Нет экранов обучения, ленты, чата, match%.

## 16. Launch requirements (требования к запуску)

- Staging проверен по smoke.
- Политика ПДн опубликована.
- Есть модератор и канал связи.
- ≥15 обещанных реальных объявлений (операционный критерий, не фича).
- Аналитика пишет события.

Не требование запуска: Matching, Radar, избранное.
