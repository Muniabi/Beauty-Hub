# 07 — UX Architecture (UX-архитектура)

**Связано:** [04 — PRD](04-prd.md) · [06 — User Stories](06-user-stories.md) · [11 — Telegram](11-telegram-architecture.md) · **канон экранов:** [24](24-implementation-spec.md) §3

Принципы: mobile-first, мало шагов, понятные empty / loading / error. Не превращать навигацию в «портал холдинга». Каталог Masters **нет в MVP** — иначе соцсеть.

---

## Отличие от исходной карты сайта

Исходник предлагал `Masters`. В MVP раздела нет: нет JTBD P0 «смотреть людей» и есть риск Non-Goal. Поиск людей — P1.

Home **не** является Radar. Блок «новые объявления» показывается только если есть `published`; иначе честный empty (DEC-11). Детали главной: [24 §3](24-implementation-spec.md).

## Information Architecture (информационная архитектура)

```text
Website (веб-платформа)
├── Home (главная)
├── Search (поиск / единый каталог с типом)
│     фактически те же сущности, что ниже
├── Spaces (помещения)
├── Events (мероприятия)
├── Jobs (вакансии)          ← вместо Masters
├── Create (создание)
├── Profile (профиль)
├── Settings (настройки)
├── Legal (политика, правила)
└── Admin (не в публичной навигации)
```

**Почему Jobs, не Vacancies в URL:** понятнее на русском в UI («Вакансии и поиск работы»), path может быть `/jobs`.

Поиск — один маршрут `/search?type=` с чипами. `/spaces` `/events` `/jobs` — пресеты того же экрана (desktop-меню ведёт туда). Заморожено DEC-10, [24](24-implementation-spec.md).

## Navigation (навигация)

**Mobile (нижняя панель, заморожено DEC-10):**

1. Главная — `/`  
2. Поиск — `/search` (чипы типов; по умолчанию Кабинеты)  
3. Создать — `/create`  
4. Профиль — `/profile`  

Пункта «Уведомления» нет. Spaces/Events/Jobs на mobile — чипы и ссылки с Главной / desktop-меню.

**Desktop:** горизонтальное меню: Главная, Кабинеты, События, Вакансии, Создать, Профиль / Войти.

Гость: те же разделы, CTA «Войти через Telegram».

## Empty / loading / error

**Empty список:** «Пока нет кабинетов в этом районе. Подпишитесь в Telegram — напишем, когда появятся.» Кнопки: сбросить фильтр, открыть бота.

**Empty главная до seed:** не имитировать активность. Честно: «Собираем объявления Ростова» + форма «оставить Telegram» только если это не второй продукт. Лучше: CTA организаторам «добавить МК».

**Loading:** скелетоны карточек, не спиннер на весь экран > 300 мс без скелетона.

**Error:** «Не получилось загрузить. Повторить.» Сеть / 500.

**Модерация pending у автора:** «На проверке. Обычно в течение 24 часов.» (DEC-05)

## Onboarding (первоначальное знакомство)

```text
Вход Telegram
  → Роль
  → Имя + контакт (если Login не дал username)
  → Специализация (мастер) / пропуск (supply)
  → Район
  → «Готово» → пустой поиск или создание
  → Баннер: подключить уведомления (если ещё не)
```

Цель: < 5 экранов. Не объяснять «мы не Avito».

Критерий успеха: `profile_completed`.  
Аналитика: `user_registered` → `profile_completed`.  
Fallback: можно смотреть каталог без онбординга; создание блокируется.

## Listing creation (создание объявления)

```text
Создать → тип (кабинет / событие / вакансия)
  → поля типа
  → фото
  → предпросмотр
  → отправка на модерацию
```

Ошибки: файл слишком большой, нет района, дата события в прошлом.  
Fallback: сохранить draft.  
Успех: экран «Отправлено на проверку».  
Событие: `listing_created`.

## Search flow (сценарий поиска)

**Цель:** найти релевантную карточку.  
**Вход:** таб Поиск, главная, deep link из Telegram с query.  
**Шаги:** тип → фильтры → список → карточка.  
**Ошибки:** 0 результатов, таймаут.  
**Fallback:** empty + Telegram.  
**Успех:** `listing_viewed`.  
**События:** `search_performed`, `filter_applied`.

---

## Matching flow (сценарий подбора)

P1. В MVP **не проектировать отдельный экран «вам подходит»**.

После беты: намерение из текущих фильтров → «Сообщить о новых» → уведомление. Успех: `match_created` + переход по ссылке.

---

## Telegram flow (сценарий Telegram)

**Цель:** привязка и типы.  
**Вход:** Settings, баннер, /start.  
**Шаги:** см. [11](11-telegram-architecture.md).  
**Ошибки:** бот заблокирован пользователем.  
**Fallback:** только сайт и канал (публичный).  
**Успех:** `telegram_connected`.  
**Событие:** то же.

Не заставлять пользоваться ботом для поиска.

---

## Notification flow (сценарий уведомлений)

**Цель:** узнать о новом published своего типа.  
**Вход:** push Telegram.  
**Шаги:** сообщение → тап URL → карточка сайта.  
**Ошибки:** битая ссылка (объявление уже expired) — экран «объявление неактуально».  
**Успех:** `listing_viewed` с source=telegram.  
**События:** `notification_sent`, `notification_opened` (через UTM `utm_source=telegram`).

---

## Profile flow (сценарий профиля)

**Цель:** контакт и роль правдивы.  
**Вход:** таб Профиль.  
**Шаги:** просмотр, правка, мои объявления.  
**Ошибки:** upload.  
**Успех:** сохранение.  
**Событие:** повторный `profile_completed` не слать; отдельный `profile_updated` опционален P1.

---

## Moderation flow (сценарий модерации)

**Цель:** не пропустить мусор и не держать добросовестных сутками без SLA.  
**Вход:** /admin.  
**Шаги:** очередь pending → карточка → approve/reject.  
**Ошибки:** нет.  
**Fallback:** вручную в Telegram написать автору.  
**Успех:** published + канал.  
**Событие:** внутреннее moderation_action (аудит).

## Критика навигации исходника

Пункт Masters убран. Create в таббаре — осознанно: supply должен публиковать за 2 тапа. Если бета покажет, что 90% гости-мастера, Create можно спрятать в профиль — пересмотр по метрике `listing_created` от ролей.
