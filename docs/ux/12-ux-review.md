# 12 — UX Review (итоговая проверка U0)

Проверка пакета `docs/ux/` против [../24-implementation-spec.md](../24-implementation-spec.md) и принципа:

> Быстро найти актуальную профессиональную возможность в beauty-индустрии Ростова и быстро связаться с её автором.

---

## Discoverability (понятность без объяснения)

**Вердикт:** достаточна для MVP, если hero и три плитки на Home сделаны крупно.

Новый пользователь видит: город в подписи, три типа пользы, не ленту коллег. Риск: слово «инфраструктура» в документации не должно попасть в UI — в UI уже бытовые «кабинеты / мастер-классы / вакансии».

Онбординг не карусель — роли ясные.

---

## Speed (скорость найти объявление)

**Вердикт:** путь Home → тип → список короткий (1–2 тапа до списка).

Нет «Все» — список однородный, 2–3 секунды на карточку реальны (бейдж + район + цена/дата). Фильтры спрятаны в sheet, не перегружают первый кадр.

Узкое место: пустой seed — скорость не поможет, нужна операционка, не UX.

---

## Contact (Listing → Login → Contact)

**Вердикт:** путь спроектирован, context `next` обязателен, в том числе через онбординг.

Не ломается, если реализация не сбросит query. Жалоба не конкурирует с CTA у гостя. Контакт не в списке — меньше случайных раскрытий.

Риск: Telegram Widget на мобильном браузере — продуктовый, не UX-схемы; fallback в UI есть (ошибка + retry), phone auth нет.

---

## Mobile (одна рука)

**Вердикт:** TabBar 4 пункта, Create по центру, sheet фильтров снизу, карточка вертикальная одна колонка.

CTA контакта в потоке, не обязательный sticky (упрощение MVP). Длинные описания — минус; для кабинетов обычно коротко.

---

## Create

**Вердикт:** тип → один скролл формы → preview → pending. Не 8 шагов.

Черновик есть. Published edit → pending объяснён. Обязательные поля соответствуют spec §3.7.

Риск: фото ≥1 для Space на мобильном — стандартная боль upload; состояния ошибки файла описаны.

---

## Moderation

**Вердикт:** FIFO очередь, approve в два тапа, reject с причиной. Не CMS.

Модератор видит тип, автора, время, жалобы. Mobile compact предусмотрен.

---

## MVP Discipline

**Не появились:** избранное, featured, Radar, «Все», лента, Mini App, каталог людей, matching, чат, обучение.

**Сознательно отклонено от формулировок запроса U0:** чип «Все», infinite scroll, favorite.

---

## Принятые UX-решения (сводка)

| ID | Решение |
| --- | --- |
| UX-DEC-01 | Нет смешанного фида «Все» |
| UX-DEC-02 | Нет избранного |
| UX-DEC-03 | Нет featured |
| UX-DEC-04 | Одно поле поиска по названию |
| UX-DEC-05 | «Показать ещё», не infinite |
| UX-DEC-06 | Автор только на странице |
| UX-DEC-07 | Вертикальная карточка mobile |
| UX-DEC-08 | `next` через логин и онбординг |
| UX-DEC-09 | Подписи «Кабинеты / Мероприятия / Вакансии» |
| Home | Один блок «новые» по приоритету space→event→vacancy |
| Login | Полная страница, не sheet |
| Фильтр спец. | Одна специализация в фильтрах |
| Sticky CTA | Нет в MVP, CTA в потоке |
| Tablet | TabBar + 2 колонки |

| Кому | Что |
