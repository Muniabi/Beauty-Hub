# 05 — Guest → Login → Contact (поток контакта)

**Канон:** DEC-03, DEC-04, P-1 в [../24-implementation-spec.md](../24-implementation-spec.md) · AC в [02](02-user-flows.md)

Это **главный UX-flow MVP**. Каталог публичный. Контакт — только после Telegram Login.

---

## 1. Сценарий

```text
Guest
 ↓
Browse public catalog
 ↓
Open listing
 ↓
Click Contact
 ↓
Telegram Login
 ↓
Return to the same listing
 ↓
Contact becomes available
```

---

## 2. Состояния A–F

### A. Гость на карточке

Видит контент, **не** видит телефон и @username в DOM как открытый текст. CTA: **«Войти, чтобы написать»** (не «Показать контакт» — иначе кажется, что контакт уже есть).

Вторичные: Жалоба скрыта или ведёт на login с next на карточку. **Решение:** Жалоба только после входа; гостю не показывать.

### B. Login prompt

Не модалка поверх с двумя кнопками «отмена/ок» без контекста. Либо:

- переход на `/login?next=/listings/{id}`, или
- sheet: короткий текст «Чтобы написать автору, войдите через Telegram» + кнопка входа + Отмена.

**Решение U0:** **полноэкранный `/login`** с `next`. Проще Telegram Widget, нет обрыва hash. Sheet — лишний паттерн.

На login: заголовок «Войти через Telegram», одна кнопка/виджет, ссылки legal, «Назад» на карточку (next уже в URL — назад = listing без логина).

### C. Telegram authentication

Нативный виджет / редирект Telegram. Ошибка: «Не получилось войти. Попробуйте ещё раз.» Без phone fallback (DEC-04).

### D. Успешная авторизация

Сессия cookie. Если нет `profile_completed` → онбординг с тем же `next` в query на всех шагах (`/onboarding/role?next=...`).

### E. Возврат на исходную страницу

Редирект строго на `next`, если `next` — относительный путь того же origin (`/listings/uuid`). Иначе — `/`. Не открывать Home «по умолчанию».

### F. Contact доступен

CTA primary: **«Написать в Telegram»** → `https://t.me/{username}` или `tg://` ; если только numeric — ссылка `https://t.me/+...` не выдумывать: показать «Открыть Telegram» по username; если в профиле хранится username — его.

Secondary: **«Позвонить»** только если `contact_phone` заполнен.

Событие: `contact_clicked` на успешном раскрытии/клике API contact.

Повторный заход: контакт можно не прятать снова в той же сессии на этой карточке (уже unlocked).

## 3. Сохранение context

| Параметр | Значение |
| --- | --- |
| Ключ | `next` |
| Пример | `/login?next=%2Flistings%2Fabc` |
| Онбординг | прокидывать `next` на каждом шаге |
| После skip notify | всё равно `next` |
| Создать | `next=/create` |
| Профиль | `next=/profile` |
| Защита | только внутренние пути, reject `//evil.com` |

Не заставлять заново искать объявление.

## 5. Онбординг в этом потоке

Не объяснять «мы не Avito». Три коротких шага. Notify — skip. Специализация обязательна только master.

Если пользователь закрыл онбординг на середине: Create и Contact заблокированы до completed; каталог смотреть можно. **Решение:** незавершённый онбординг при повторном Contact снова кидает на онбординг с `next`.

---

## 6. Ошибки

| Ситуация | UI |
| --- | --- |
| Виджет Telegram недоступен | текст ошибки + retry |
| Сессия истекла на карточке | снова CTA гостя |
| API contact 401 | как гость |
| API contact 429 | «Слишком много запросов. Подождите.» |

---

## 7. Что не делать

Встроенный чат, показ телефона гостю «для удобства», email-логин, принудительная подписка на все уведомления ради контакта.
