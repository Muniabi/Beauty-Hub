# 04 — Search (поиск)

**Канон:** [../24-implementation-spec.md](../24-implementation-spec.md) §3.8 · [00 UX-DEC-01, 04, 05](00-ux-blueprint.md)

Не маркетплейс-поиск Avito. Один тип в момент времени. Сортировка только «сначала новые».

---

## 1. Цель

Найти карточку своего типа за минимум жестов. Сканирование списка важнее «умного» query.

---

## 2. Состав экрана

### Всегда

- Чипы типа: **Кабинеты | Мероприятия | Вакансии**. Ровно один выбран. Дефолт с таба Поиск: **Кабинеты**.
- Поле `q`: плейсхолдер «Название». Поиск по заголовку (ILIKE). Не геокодер.
- Список `ListingCard`.
- Подпись: «Сначала новые». Без выпадающей сортировки.
- «Показать ещё» при наличии следующей страницы.

### Нет

- Чип «Все» (UX-DEC-01).
- Карта.
- Infinite scroll (UX-DEC-05).
- Сохранение поиска / matching.

### Фильтры (зависят от типа)

Общие: район, специализация (мульти необязательно — **решение:** один select специализации в MVP для простоты; мульти на карточке объявления сохраняется).

`DECISION REQUIRED` слабо: мульти-фильтр специализаций vs одна. **Предложение U0:** в фильтрах **одна** специализация или «все направления». Проще большим пальцем.

Space: цена от–до (два числа).  
Event: дата от (datepicker), дата до опционально.  
Vacancy: чипы direction: Все направления вакансии / Ищу мастера / Ищу работу. Здесь «Все» **внутри типа** допустимо (не смешение кабинетов с МК).

## 3. Mobile

```text
┌ Чипы типа (горизонтальный скролл не нужен: 3 чипа) ┐
│ [Кабинеты] Мероприятия Вакансии                     │
│ [ Название                              ]           │
│ [ Фильтры 3 ]   если активны — бейдж числа          │
│ карточка                                            │
│ карточка                                            │
│ [ Показать ещё ]                                    │
└ таббар ┘
```

«Фильтры» открывает **bottom sheet**: район, специализация, поля типа, кнопки «Сбросить» и «Показать». Число на кнопке = число заданных ограничений (не считая типа).

Клавиатура: поле названия не автофокус при входе на таб (не прыгает экран).

---

## 4. Desktop

Чипы + поле q в одну линию. FilterBar сверху или колонка 240px слева. Список 2–3 колонки карточек. «Показать ещё» по центру снизу.

Header «Кабинеты» = `/search?type=space` (и алиас `/spaces`).

---

## 5. Состояния

| ID | Когда | UI |
| --- | --- | --- |
| Loading | первый запрос | 3–6 SkeletonCard, чипы на месте |
| Empty seed | 0 published этого типа, фильтров нет | «Пока нет кабинетов в Ростове. Если сдаёте — добавьте карточку.» CTA Создать + не врать лентой |
| Zero results | фильтры/q дали 0 | «Ничего не нашли. Сбросьте фильтры или включите уведомления в Telegram — напишем, когда появится.» CTA: Сбросить фильтры; вторичная: Настройки уведомлений (если авторизован) / Войти |
| Error | 5xx / сеть | «Не получилось загрузить. Повторить.» |
| Success | есть items | список + ещё |
| Unauthorized | не применяется к просмотру | — |

Пустой seed ≠ zero-results: разный copy.

---

## 6. Пагинация

Размер страницы `ASSUMPTION`: 20. Кнопка «Показать ещё» дописывает в список, скролл не сбрасывать. Нет автоподгрузки при достижении низа.

---

## 7. Поведение чипов

Смена типа сбрасывает фильтры, специфичные для предыдущего типа (цена/дата/direction), сохраняет район и специализацию если применимы. `q` можно сохранить.

## 9. A11y

Чипы — `role=tab` или radio group с подписью «Тип объявления». Sheet: focus trap, Escape закрывает. Кнопка фильтров объявляет «фильтры, задано N».
