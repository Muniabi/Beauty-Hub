## Product (продукт)

**Есть ли чёткая проблема?**  
Да: нет единого профессионального информационного слоя для мастеров города; чаты теряют объявления; организатор и владелец кабинета не доходят до аудитории. Источник — заявленные боли, не измерение.

**Есть ли подтверждаемая гипотеза?**  
Да, и она помечена `HYPOTHESIS`: структурированные Space/Event/Vacancy + Telegram по типу → повторное использование и отклики. Способ проверки: интервью, seed, бета, прокси `contact_clicked` + ручной follow-up.

**Не слишком ли большой MVP?**  
Исходник был слишком большим (бот-CRUD, Mini App, Match scoring, Radar, Club, каталог мастеров). Пакет **урезал** до P0 в [05](05-mvp-scope.md). Остаточный риск: три типа объявлений + Telegram + админка всё ещё много для одного разработчика — это названо; concierge до кода обязателен. Дальше резать можно только выкинув один тип после интервью (R-15).

**Есть ли network effect?**  
Описан как гипотеза, не факт. Обратная сторона (пустота) учтена seed-first.

**Решает ли продукт реальную проблему?**  
Неизвестно. Единичный сигнал барбера `VALIDATED` как запрос, не как рынок. **К реализации ядра кода переходить нельзя** до Phase 0.

## UX

**Зачем возвращаться?**  
Episodic спрос на кабинет + привычка Telegram. Не ежедневная лента (Non-Goal). Честно: удержание мастера может быть уведомлениями, не Home. Radar не P0, чтобы не врать «сегодня 0».

**Минимально ли действий?**  
Создание — тип → форма → модерация. Поиск — чипы типов. Контакт — после логина (трение сознательное против скрейпа).

**Не перегружен ли интерфейс?**  
Раздел Masters убран. Таббар без семи пунктов. Риск: три раздела + поиск дублируют IA — смягчено пресетами.

## Engineering (разработка)

**Overengineering?**  
Нет микросервисов, K8s, ES, Kafka, LLM. Modular monolith + PostgreSQL. Redis отложен по сигналу.

**Boundaries?**  
Модули в [08](08-system-architecture.md); Telegram не размазан (ADR). Риск комка при одном репозитории — ADR-001 revisit.

**Критические зависимости?**  
Telegram Login/API, хостинг (D-01), модератор-человек, seed.

**Fallback?**  
Сайт без бота; ручной пост в канал; SQL approve как аварийный; concierge Notion.

## Оставшиеся противоречия / напряжения (не спрятаны)

1. **Telegram-first vs веб-формы:** привычка в TG, сложные сценарии на сайте. Намеренно. Риск, что мастера не откроют сайт — измерять CTR.
2. **Три типа vs фокус:** исходник хочет всё; дифференциация от Avito сильнее на событиях. Интервью могут выкинуть Space или наоборот.
3. **Контакт после логина vs трение конверсии:** безопасность vs UX. D-03 рекомендация, не священна.
4. **Opt-in vs холодный старт уведомлений:** меньше спама, меньше «магия сама находит». Пересмотреть, если 0 opt-in при живых карточках.
5. **Салон vs Space Owner** почти одна персона — возможное слияние ролей в реализации (не блокер).

### Можно ли переходить к реализации?

Состояние **после заморозки [24](24-implementation-spec.md)** (DEC-17):

- **UX/UI (U0):** да, сразу.
- **Код Foundation (E1):** можно параллельно с U0.
- **Закрытая бета:** нет, пока нет seed, модератора и минимума согласия/ПДн (D-02).

Условия беты:

- [ ] ≥8 интервью **или** явный concierge-риск Product
- [ ] ≥15 обещанных реальных объявлений
- [ ] Модератор назван
- [ ] План D-02
- [ ] Нет попытки втащить Match/Club/обучение в тот же релиз

### Готовность документации как системы

Пакет связан ссылками, единым словарём и ID требований/историй/рисков. Это **Product & Engineering система документации**, пригодная к декомпозиции задач после отдельного подтверждения Discovery.

Не готово: юридические документы, **дизайн-макеты** (следующий шаг — U0 в [24](24-implementation-spec.md)), оценка трудозатрат в часах, состав команды, бюджет рекламы.

## Дополнение 2026-08-31 — заморозка реализации

После аудита 00–23 создан [24 — Implementation Specification](24-implementation-spec.md). Он закрывает противоречия, которые в первом аудите оставались «напряжениями»:

- D-03 контакт после входа — **заморожено**
- D-04 только Telegram Login — **заморожено**
- Admin **до** Telegram
- 3 роли вместо 4 (`salon_owner` слит)
- Таббар 4 пункта, без Radar на главной
- Opt-in уведомлений (default false)
- DEC-17: UX стартует сразу; бета по-прежнему с seed

### Можно ли переходить к UX/UI?

**Да.** Инвентарь экранов и DoD дизайна — [24 §3](24-implementation-spec.md).

### Можно ли переходить к коду MVP?

**К Foundation (E1) — да, параллельно с U0**, если Product дал старт реализации.  
**К закрытой бете — нет**, пока нет seed, модератора и минимума D-02.

Первый аудит («не к продуктовому коду») относился к состоянию *до* заморозки и трактовал Discovery как абсолютный стоп. Это снято DEC-17 для дизайна и фундамента, не для публичной беты.
