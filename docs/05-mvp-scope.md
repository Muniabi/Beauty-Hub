# 05 — MVP Scope (объём MVP)

**Связано:** [04 — PRD](04-prd.md) · [06 — User Stories](06-user-stories.md) · [20 — Roadmap](20-roadmap-backlog.md) · **замороженный состав:** [24](24-implementation-spec.md) §2

Цель файла — предотвратить feature creep (разрастание функций). Если функции нет в P0, её нет в первом релизе беты.

---

## Правило включения

Функция в P0 только если:

1. Закрывает Primary JTBD-01…06 или гигиену marketplace; и
2. Имеет критерий проверки; и
3. Не тянет продукт в Non-Goals ([01](01-product-vision.md)).

---

## P0 — Must Have (обязательно)

Без этого MVP не проверяет гипотезу «структурированный слой + Telegram по типу».

### F-P0-01 Authentication (аутентификация)

| Поле | Значение |
| --- | --- |
| Why | Публикация, контакт, антискрейп контактов |
| User | Все |
| Value | Идентичность |
| Complexity | Средняя (Telegram Login) |
| Priority | P0 |
| Dependencies | Telegram |
| Как проверить необходимость | Без входа нельзя отличить ботов и посчитать контакт |
| Минимальная реализация | Только Telegram Login |
| Сигнал вверх/вниз | Отказ пользователей от Telegram Login → рассмотреть phone OTP (P1) |

### F-P0-02 Profiles (профили)

| Why | Контакт и роль |
| User | Все |
| Value | Доверие минимума |
| Complexity | Низкая |
| Dependencies | Auth |
| Минимум | Имя, роль, контакт; фото необязательно |
| Сигнал | Бросают онбординг → укоротить поля |

### F-P0-03 Specializations (специализации)

| Why | Фильтр и карточка |
| Complexity | Низкая (справочник) |
| Минимум | Фиксированный enum |
| Сигнал | Часто «другое» в интервью → расширить справочник |

### F-P0-04 Listings Space / Event / Vacancy

| Why | Ядро ценности |
| User | Supply создаёт, Master потребляет |
| Complexity | Высокая (форма, фото, статусы) |
| Dependencies | Profile, storage, модерация |
| Минимум | Три типа, без коллабораций |
| Как проверить | Seed: реальные карточки; если салоны не дают Space — гипотеза supply мертва |

### F-P0-05 Search + Filters (поиск и фильтры)

| Why | Иначе это канал без сайта |
| Complexity | Средняя |
| Минимум | Тип, район, специализация, цена, дата события; сорт по новизне |
| Сигнал | Никто не фильтрует → упростить UI |

### F-P0-06 Contact (контакт)

| Why | Единственный путь к соединению в MVP |
| Complexity | Низкая |
| Минимум | Кнопка после логина |
| Сигнал | 0 кликов при просмотрах → карточка/доверие |

### F-P0-07 Telegram connect + type subscriptions + channel

| Why | Гипотеза Telegram-first |
| Complexity | Средняя/высокая |
| Dependencies | Published listings |
| Минимум | Три флага типа, сообщение со ссылкой, канал |
| Не делать | Мастер создания объявления в боте, Mini App, поиск в боте |
| Сигнал | 0 привязок бота → канал-only; пересмотреть Telegram-first |

### F-P0-08 Reports + Moderation + Admin

| Why | Marketplace без модерации = свалка |
| Complexity | Средняя |
| Минимум | Pending queue, reject, reports inbox |
| Сигнал | Очередь > SLA → ужесточить правила или больше часов модератора |

### F-P0-09 Analytics events (события аналитики)

| Why | Иначе не узнать, работает ли продукт |
| Complexity | Низкая |
| Минимум | Список из [14](14-analytics.md) P0-событий |

### F-P0-10 Legal + account deletion

| Why | Публичные ПДн и контакты |
| Complexity | Низкая/средняя (тексты — D-02) |
| Минимум | Страницы + удаление аккаунта |

## Won't Have (сознательно не входит)

| Функция | Почему нет |
| --- | --- |
| Онлайн-школа, видео, материалы | Прямой запрет заказчика; смещение категории |

| Встроенный мессенджер | Сложность, дубль Telegram; исходник исключал из MVP |

| Онлайн-оплата аренды и билетов | Не инфраструктура объявлений; юр. и поддержка |
| AI / LLM рекомендации | Нет данных, стоимость, не проверяет JTBD |
| Elasticsearch | Мало документов |
| Микросервисы, Kubernetes, Kafka | Масштаб команды |
| NFT / blockchain | Нет задачи |
| Рекламный кабинет бренда | Нет аудитории |
| Сложная CRM | Не продукт |
| Matching «Tinder» / процент совместимости | После простых правил |

## Оценка P0 по ценности и риску

| Функция | User Value | Business Value | Tech Complexity | Risk если не сделать | Risk если сделать рано |
| --- | --- | --- | --- | --- | --- |
| Auth+профиль | Высокая | Высокая | Средняя | Нет публикации | — |
| Три типа listing | Критическая | Критическая | Высокая | Нет продукта | Слишком много полей |
| Поиск | Критическая | Высокая | Средняя | Канал без базы | — |
| Telegram типы | Высокая | Высокая | Средняя | Нет привычки | Спам, если все типы сразу без настроек — настройки обязательны |
| Админка | Средняя для юзера | Критическая | Средняя | Свалка | — |
| Matching | Высокая позже | Высокая позже | Высокая | — | Пустые «0 предложений» |
| Каталог мастеров | Неясная | Низкая | Средняя | — | Соцсеть |

Оценки качественные, без ложной точности RICE. Данные, которые изменят приоритет: интервью (события vs кабинеты), конверсия seed, отказы от Telegram Login.

## Минимальный срез для проверки гипотезы (ещё уже, чем полный P0)

Если ресурсы критически малы, **ручной процесс** вместо автоматизации (см. [21](21-dependency-map.md)):

1. Тильда/простые страницы **не** заменяют статусы и фильтры надолго, но **таблица + канал** могут проверить спрос **до** кода: собрать 20 объявлений вручную в Notion и постить в Telegram.
2. Это Discovery Phase 0, не отказ от P0. Код начинать после сигнала, что карточки открывают и пишут.

Документация описывает полный P0 как первый **программный** продукт. Phase 0 concierge — рекомендуется до Этапа 1.

## Сознательно отложенный Matching

Исходник ставил Beauty Match как главную фишку. Планирование зафиксировало: **после закрытой беты**.

Условие повышения до разработки Matching:

- Есть регулярные `published` объявления (порядок: не ноль каждую неделю; точное N = TBD).
- Пользователи возвращаются или открывают Telegram.
- Есть запрос на «скажите, когда появится под мой фильтр».

Условие понижения: никто не фильтрует район/специализацию — тогда даже Search Intent не нужен.
